**Symptom:** `tskip()` does not skip anything. It prints its arguments and returns, so a test that
gates itself off and calls `tskip()` runs to completion with zero assertions and is reported as
**`✓ PASS`**. The run summary shows `Skipped: 0`.

The consequence is not cosmetic. Every platform-gated, depth-gated or tool-gated test in every
project using TestMe is contributing a green tick to its suite's headline number while never
executing. A reader of that number cannot distinguish "this passed" from "this never ran".

**Errant code** — `src/modules/js/index.js:306`:

```js
function tskip(...args) {
    console.log(...args)
}
```

For comparison, its neighbours are the same one-line shape, which is correct for *them* — they are
output helpers:

```js
function tdebug(...args) {
    console.log(...args)
}

function twrite(...args) {
    console.log(...args)
}
```

`tskip` is grouped with them under `// Output functions` in `src/modules/js/index.d.ts:186-191` and
typed identically, `export function tskip(...args: any[]): void`. So the name promises control flow
and the implementation delivers logging.

**Steps to Reproduce:**

```sh
cat > /tmp/x/skip.tst.ts <<'EOF'
import {tskip} from '@embedthis/testme'
tskip("not applicable here")
EOF
cd /tmp/x && tm
```

Observed:

```
✓ PASS skip.tst.ts
✓ Passed:  1
- Skipped: 0
Result: PASSED
```

Expected: reported as skipped, `Skipped: 1`, and not counted as a pass.

**How this was found, and what it had been hiding.** During the second security audit of Appweb
(appweb #10344), `test/leak/valgrind.tst.ts` — that product's only memory-leak test — was found never
to have executed on any machine. It gates on
`Config.OS == 'linux' && tdepth() >= 4 && Cmd.locate("valgrind")` and calls `tskip()` otherwise. On
macOS, where the suite actually runs, it therefore reported `✓ PASS` on every run for years while
carrying **four** independent defects that made it unrunnable: a dependency on an `http` client the
repo does not build, a `--suppressions` path nothing produces (valgrind treats a missing one as
FATAL), an assertion that could not fail on a leak, and an `appweb.conf` written for Appweb 4/5 that
the server rejects on its first directive.

None of those four could be noticed, because the test's outcome was indistinguishable from success.
That is the whole cost of this defect: it does not create bugs, it hides the fact that nothing is
looking for them.

The same pattern is live elsewhere in that suite — `test/cgi/windows-shell-fallback.tst.ts` gates on
Windows and skips everywhere the suite runs, and it is the sole test for a Critical unauthenticated
RCE.

**Proposed solution**

1. **Make `tskip()` actually skip.** It should record a skip outcome for the current test file and
   stop execution of it — the same way a failing assertion terminates the file — rather than
   returning and letting the file fall through to its end.
2. **Report skips as a distinct outcome.** They already have a slot in the summary (`- Skipped: N`),
   which is currently always zero from this path. A skipped test must not increment `Passed`.
3. **Print the reason with the result**, not only to stdout, so `✓ PASS` / `- SKIP <reason>` reads
   correctly in a scrollback and in CI output.
4. **Move `tskip` out of the "Output functions" group** in `index.d.ts` and give it a return type
   that reflects that it does not return normally, so the API stops implying it is a `console.log`
   variant.
5. **Consider making a zero-assertion test file a warning**, independent of this fix. A file that
   completes having asserted nothing is nearly always a gate that silently swallowed its own body,
   and that heuristic would have caught the Appweb leak test even before `tskip` was called.

**Files to Investigate:**
- `src/modules/js/index.js:306` — `tskip`
- `src/modules/js/index.d.ts:186-191` — the `// Output functions` grouping and signature
- wherever the runner tallies `Passed` / `Failed` / `Skipped` for a test file
- the C and shell test harnesses, which need the same concept — `test/security/casefold-documents-linux.tst.sh`
  in Appweb echoes `SKIP:` and exits 0, which is the same defect in a different language

**Verification Criteria:**
1. A test file that calls `tskip()` is reported as skipped, not passed, and increments `Skipped`.
2. The reason passed to `tskip()` appears alongside the skip in the result output.
3. Code after `tskip()` in the same file does not execute.
4. A suite of one passing, one failing and one skipped test reports `1 / 1 / 1`, not `2 / 1 / 0`.
5. `tm` passes in this repo.

**Root Cause:** `tskip()` printed and returned. A gated test then ran off the end of its file with zero assertions and exit status 0, and every handler derives a test's status from the exit code alone, so the file was recorded as a pass. Nothing in the pipeline had a way to express "did not run" for a test that had started.

**Fix Applied:** A test now reports that it did not run with its **exit status**, following the Automake convention: `TM_EXIT_SKIP` = 77. This is a single language-neutral protocol rather than a per-language mechanism, so a shell, Python or Go test skips itself by exiting 77 with no helper at all.

- `src/types.ts:1-13` — `TM_EXIT_SKIP` (77) and `TM_SKIP_PREFIX` (`SKIP:`), plus `skipReason` on `TestResult`.
- `src/handlers/base.ts:503-521`, `:556-566` — `createTestResult()` maps exit 77 to `TestStatus.Skipped` and lifts the reason out of the output. Every handler already routes through here and passes the exit code, so all nine languages are covered by the one change.
- `src/reporter.ts:87`, `:100`, `:207`, `:166`, `:260-270` — the reason is printed beside the result (`- SKIP path (15ms) - no kettle on this platform`), in the detailed report, and in the JSON output.
- `src/modules/js/index.js:13-18`, `:313-322` — `tskip()` prints `SKIP: <reason>` and exits 77.
- `src/modules/c/testme.h:48-54`, `:801-820` — the same for C.
- `src/modules/es/testme.es` — the same for Ejscript.
- `src/modules/js/index.d.ts:186-203` — `tskip` moved out of the "Output functions" group and typed `never`, so the API no longer implies it is a `console.log` variant.
- `src/modules/es/Makefile:12` — a missing `; \` broke the `testme.mod` recipe whenever `testme.es` was newer than `testme.mod`. `make build` could not complete once the module was touched.
- `README.md`, `README-C.md`, `README-JS.md`, `doc/tm.1` (new "Test Exit Status" section), `CLAUDE.md` — documented, including the exit-77 route for languages without a helper.

Skips already had a slot in the summary and were already excluded from the run's failure predicate, so no tallying change was needed once the status was set correctly.

**Tests Added:** `test/skip-outcome.tst.ts` (21 assertions) drives `tm` over the fixtures in `test/skip/` and checks the whole path: a skipping test is counted under `Skipped` and not `Passed`, the reason is reported, the sentinel assertion after `tskip()` never runs, a run whose only test skipped exits zero and reads `PASSED`, and a one-pass/one-fail/one-skip suite tallies 1 / 1 / 1. Covers both the TypeScript and the C helper. Run with `make test`. Verified failing against the unfixed `tskip` (the fixture reached its sentinel and reported FAIL) before passing against the fix.

**Verification:** Full suite 54 passed / 1 skipped / 386 assertions.

**Not done:** proposal 5 (warn on a zero-assertion test file) is filed separately as [#10008](10008.md) — the ticket calls it independent of this fix, and it is a heuristic rather than part of the skip protocol.
