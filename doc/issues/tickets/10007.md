**Symptom:** When one configuration group's `environment`, `prep` or `setup` service fails, the run prints that group's error and stops. No `TEST SUMMARY` is printed, and no failure detail for any test in any earlier group -- not the assertion text, not the expected and received values, not the compiler output for a test that failed to build. A suite that ran hundreds of tests reports nothing but the one service error.

The live `✓ PASS` / `✗ FAIL` lines still stream as each test finishes, so the run looks like it reported. It did not: every one of those failures is unexplained.

**Steps to Reproduce:**
1. Take a suite with at least two groups, where an earlier group has a failing test and a later group has a `setup` service that cannot start (for example, its port is already held).
2. Run `tm`.
3. Observe: the earlier group's `✗ FAIL` line appears, then the later group's setup error, then the process exits. No summary, and no detail for the earlier failure.

**Cause:** In `src/index.ts` the per-group block is `try { services; execute } finally { cleanup }` with no `catch`. A throw from `runEnvironment`, `runPrep` or `runSetup` unwinds out of the group loop, past `allResults.push(...)`, past the remaining groups, and past the `reportFinalResults` call that follows the loop. It is caught only by the top-level handler, which prints `❌ Error: <message>` and exits.

**Expected Behavior:**
- A service failure in one group fails that group and is reported as such. It does not suppress the results of groups that already ran.
- The final summary and every failure's detail are printed regardless of which group failed and how.

**Files to Investigate:**
- `src/index.ts` - the per-group `try`/`finally` around the service calls and `executeTestsWithConfig`
- `src/services.ts:606` - where the setup failure is thrown

**Verification Criteria:**
1. Reproduce as above.
2. Verify: the summary prints, the earlier group's failure detail prints, and the exit code is non-zero.

**Investigation History:**
- 2026-09-08: Found while diagnosing why an Ioto Windows CI run showed nine failing tests and no explanation for any of them. The run's last group had a setup service that could not bind its port.
- 2026-09-08: Fixed by catching the error in the group loop, reporting it, marking the group failed and continuing. Verified against the original reproduction: before, the run printed only the service error; after, it prints the full summary (23 passed, 1 failed, 30255/30256 assertions) and the failing assertion's expected and received values.
