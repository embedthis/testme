# Context: Bug Fixes Session - 2025-10-07

## Summary

Completed three critical bug fixes for TestMe related to working directory handling, configuration management, and compiler warnings.

## Issues Resolved

### 1. Bun Compiled Binary Working Directory Issue

**Problem:**
- Running `tm --list` from `/Users/mob/c/r/test` showed "No tests discovered"
- Bun compiled binaries change the working directory to the embedded source location
- Tests could not be discovered from directories outside the TestMe source tree

**Solution:**
- Created a shell wrapper approach:
  - Actual binary installed as `tm-bin` (or `tm-bin.exe` on Windows)
  - Wrapper script installed as `tm` (shell script on Unix, batch on Windows)
  - Wrapper captures invocation directory with `$(pwd)` and exports as `TM_INVOCATION_DIR`
  - Binary checks for `TM_INVOCATION_DIR` on startup and restores working directory

**Files Modified:**
- [testme.ts](../../testme.ts) - Added working directory restoration logic
- [bin/install.mjs](../../bin/install.mjs) - Modified to create wrapper and install both files

**Impact:**
- Tests now correctly discovered from any working directory
- Installation still user-local (no sudo required)
- Solution is cross-platform (works on Windows, macOS, Linux)

### 2. Profile Property Not Used for Variable Expansion

**Problem:**
- `${PROFILE}` variable expansion always defaulted to 'dev' even when `profile: 'xdev'` was set in testme.json5
- Profile property from config file was being ignored

**Root Cause:**
- `ConfigManager.mergeWithDefaults()` was not preserving the `profile` property from user config
- The property existed in the TestConfig type but wasn't being included in the merge

**Solution:**
- Added `profile: userConfig.profile` to the merged config object in `mergeWithDefaults()`
- Also added `depth: userConfig.depth` for consistency

**Files Modified:**
- [src/config.ts](../../src/config.ts:192) - Added profile and depth to merge

**Priority Order (now working correctly):**
1. CLI: `tm --profile prod`
2. Config: `profile: 'xdev'` in testme.json5
3. Environment: `PROFILE=release`
4. Default: `'dev'`

### 3. Format-Truncation Warning in testme.h

**Problem:**
- GCC warning: `'%s' directive output may be truncated writing up to 4095 bytes`
- Warning triggered at line 133 in testme.h
- Caused by using buffer as both source and destination in snprintf

**Root Cause:**
- Code pattern: `snprintf(buf, sizeof(buf), "Test failed at %s: %s", loc, buf)`
- Using `buf` as both source and destination is undefined behavior
- Could theoretically truncate if formatted message was very long

**Solution:**
- Added temporary buffer `tmp` to hold the vsnprintf result
- Changed flow:
  - Old: `vsnprintf(buf, ...) → snprintf(buf, ..., buf)` (dangerous)
  - New: `vsnprintf(tmp, ...) → snprintf(buf, ..., tmp)` (safe)

**Files Modified:**
- [src/modules/c/testme.h](../../src/modules/c/testme.h:127) - Added tmp buffer, refactored treport()

**Impact:**
- Compiler warning eliminated
- Code is now safer and more correct
- Tests continue to pass
