# TestMe v0.8.34 Release Notes

Released: 2026-09-01

**No behaviour change.** This release adds regression tests that pin what the `Assertions:` summary
line counts, and records what that number does and does not mean.

## Testing

### Assertion Tally Pinned by Regression Tests

The `Assertions: N/M passed` line in the run summary was reported as unreproducible: the same suite
appeared to report 12352 assertions on one run and 4348 on another
([#10004](../issues/tickets/10004.md)).

**Finding:** `countAssertions()` is exact. It was probed against every shape the report named —
markers at the start of a line, indented, behind blank lines, mid-line, quoted as `Expected:` /
`Received:` values, and CRLF — and is correct in all of them. An instrumented per-file comparison of
two back-to-back runs of a 93-file suite found only four files whose counts moved, and both causes
are in the tests rather than in the counting:

- **A failing test truncates its own tally.** The JavaScript assertion helper exits at the first
  failing assertion, so a test that fails stops printing markers where it failed and never reaches
  the rest. A run with failures always reports fewer assertions than the same run passing.
- **A test's count can depend on state earlier tests left behind.** A test that works until a server
  resource is exhausted emits as many markers as there was room for, so it reports one number run on
  its own and another inside a full suite.

**What the number means:** the count of `✓` and `✗` result lines the tests actually printed. It is
reproducible for a fixed set of test outcomes. It is not a coverage denominator, and a run
containing failures under-reports.

**Tests added:**

- [test/assertion-counter.tst.ts](../../test/assertion-counter.tst.ts) - seven unit cases covering
  line-start, indented, blank-line-separated, adjacent, mid-line, quoted-value and CRLF markers
- [test/assertion-total.tst.ts](../../test/assertion-total.tst.ts) - drives `tm` over a fixture
  directory whose marker count is fixed by construction and asserts the tally equals it, does not
  move across two identical runs, and is the same whole as the sum of its parts
- [test/assertions/](../../test/assertions/) - the fixtures, named `*.fixture.ts` so the parent suite
  does not discover them

Both test files were verified to fail against a deliberately broken counter and to pass against the
shipped one.
